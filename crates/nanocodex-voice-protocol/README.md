# Nanocodex Voice Protocol

Shared realtime voice event parsing and adapter policy for native and browser consumers. Platform audio ownership lives in the voice adapters; this crate contains the reusable protocol boundary.

## Upstream semantics audit (2026-09-27)

Reference: [openai/codex `32f578485143354d1c321840a3e990aabdbaca9c`](https://github.com/openai/codex/tree/32f578485143354d1c321840a3e990aabdbaca9c/codex-rs).

- `app-server/src/request_processors/turn_processor.rs:1316-1366` forwards appendText role/text and appendSpeech text to core. `core/src/realtime_conversation.rs:652-655,856-881` assigns FramelessBidi to session kind V1; only V2 user text gets `[USER] `. The subscription adapter therefore correctly sends all appendText roles as unprefixed `session.context.append` input text. Wire chunks are UTF-8-safe and at most 500 bytes, matching `codex-api/src/endpoint/realtime_websocket/methods_frameless_bidi.rs`.
- `core/src/realtime_conversation.rs:1136-1159,1620-1623` bounds standalone speech to 1,000 approximate tokens. This crate now uses the same middle-preserving token marker and budget-tightening algorithm from `core/src/realtime_context.rs:318` and `utils/string/src/truncate.rs`; only V2 would add `[BACKEND] `. Speakable channel remains explicit, independent of narration settings.
- `core/src/realtime_conversation.rs:1162-1200` makes handoff completion a no-op for client-managed handoffs and V1 (including frameless). The crate likewise sends no synthetic completion ACK. Provider-created delegation alone admits work; active delegation context output and client-owned final speech remain separate modes. Steering invalidates the client speech generation and queued speakable frames; backend run identity/correlation is the host's responsibility.
- `tui/src/chatwidget/realtime.rs:345-350` restores undelivered speech and finishes partial captions when stopping. `close_effects` now completes both live speaker captions once while keeping the tail available. `core/src/realtime_conversation.rs:2187` gates transcript-tail delegation on an explicit flush flag. Hosts can now request `{"op":"tail","structured":true}` to atomically drain `{delegation, transcript:[{role,text}]}` for background persistence; legacy `tail` still returns string/null. The host controls whether the optional delegation starts work.

Remaining adapter differences: NUL public text and empty appendText are rejected; whitespace-only appendSpeech is a no-op, matching core; browser sideband reconnect uses retained acknowledged frames and a local backoff, rather than TUI session/replay machinery; it does not deduplicate replayed transcript events with upstream's transcript replay records. Provider errors terminate through effects, with extra nested-error fallback support. The host must persist structured tails and gate delegation according to session settings; this crate does not store conversations or implement app-server connection ownership/turn steering APIs. No claim of parity with V2 conversation-item wire events is intended.
