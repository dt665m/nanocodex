# Rust tools, Code Mode, and MCP

This page describes the Responses tool runtime. Claude's native capabilities use
`nanocodex-claude-tools` and Claude schemas inside the same Code Mode execution
surface. Both shipped harnesses expose only `exec` and `wait`. See the
[Claude runtime guide](https://github.com/gakonst/nanocodex/blob/master/docs/CLAUDE_RUNTIME.md)
for explicit Claude host capabilities.

Register application tools on the agent you own. The `#[tool]` macro derives
the input and output contracts from an async Rust function. `Tools::builder()`
returns `ToolsBuilder`, which selects the compiled handlers for this runtime.

```rust
use nanocodex::{Nanocodex, OpenAi, Tools, tool};

#[tool(description = "Return the production region for a service.", parallel = true)]
async fn deployment_region(service: String) -> Result<String, std::io::Error> {
    Ok(format!("{service}: us-west-2"))
}

let tools = Tools::builder()
    .without_defaults()
    .tool(deployment_region)
    .build()?;
let (_agent, _events) = Nanocodex::builder(openai).tools(tools).build()?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

Mark a tool parallel only when its local effects are safe to overlap. Implement
the `Tool` trait directly when execution needs `ToolContext`, freeform input,
multimodal output, or a custom definition.

## Model-visible exposure

Agent runtimes require Code Mode-only exposure. The model can loop,
branch, and call typed nested tools with `await tools.<name>(...)` through the
Code Mode execution surface. Only `exec` and `wait` are model-visible;
discovery and all action tools are invoked inside `exec`.

The default native workspace set includes bounded command execution, retained
stdin sessions, Rust-verified patch application, image viewing, planning, web
search, and image generation. These tools run with the embedding process's
authority. Use a private checkout, container, remote tool host, or explicit VM
boundary when local execution is not appropriate.

## Add a deferred MCP server

```rust
use nanocodex::tools::mcp::{Mcp, McpServer};

let mcp = Mcp::builder()
    .server(
        "company_docs",
        McpServer::stdio("company-docs-mcp").arg("--readonly"),
    )
    .build()?;
let tools = Tools::builder().provider(mcp).build()?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

MCP discovery starts with the owning tool runtime. Deferred schemas stay out of
the initial model prefix, are found through `tools.tool_search` inside `exec`, and become available
under canonical server/tool names in Code Mode. Native MCP is part of
`nanocodex-oai-tools`; it is not another agent runtime.

Run the [custom tool](https://github.com/gakonst/nanocodex/blob/master/examples/custom_tool.rs)
and [MCP](https://github.com/gakonst/nanocodex/blob/master/examples/mcp.rs)
examples, then read the [tools crate guide](https://github.com/gakonst/nanocodex/blob/master/crates/nanocodex-oai-tools/README.md)
for exposure, hosted Code Mode, and lower-level contracts.
